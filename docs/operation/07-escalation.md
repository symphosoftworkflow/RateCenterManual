# บทที่ 7 — การรายงานและส่งต่อปัญหา

*DOC-OPR-001 v1.0 | คู่มือการปฏิบัติงาน*

---

## 7.1 ภาพรวม

เมื่อไม่สามารถแก้ไขปัญหาได้ด้วยตนเอง เจ้าหน้าที่ต้องดำเนินการ **ส่งต่อ (Escalate)** ปัญหาไปยังบุคคลหรือทีมที่เหมาะสมตามระดับความรุนแรง

---

## 7.2 ระดับความรุนแรงของปัญหา (Severity Levels)

| ระดับ | ชื่อ | คำอธิบาย | เวลาตอบสนองเป้าหมาย |
|-------|------|---------|-------------------|
| P1 | Critical | ระบบล่มทั้งหมด ผู้ใช้งานทั้งหมดเข้าไม่ได้ | ภายใน 1 ชั่วโมง |
| P2 | High | ฟังก์ชันหลักทำงานไม่ได้ (ดึงอีเมลไม่ได้, อนุมัติไม่ได้) | ภายใน 4 ชั่วโมง |
| P3 | Medium | ฟังก์ชันรองทำงานผิดปกติ (Parser ล้มเหลวบางส่วน) | ภายใน 1 วันทำการ |
| P4 | Low | ปัญหาเล็กน้อย, คำถามการใช้งาน | ภายใน 3 วันทำการ |

---

## 7.3 ช่องทางการส่งต่อปัญหา

| ระดับ | ส่งต่อให้ | ช่องทาง |
|-------|---------|--------|
| P1, P2 | ทีมเทคนิค / ผู้พัฒนาระบบ | โทรศัพท์ + อีเมล |
| P3 | ทีมเทคนิค | อีเมล |
| P4 | ทีมเทคนิค | อีเมล |

!!! note "หมายเหตุ"
    ข้อมูลการติดต่อทีมเทคนิคให้ขอจากผู้จัดการโครงการ

---

## 7.4 แบบฟอร์มรายงานปัญหา

เมื่อส่งต่อปัญหา ต้องรวบรวมข้อมูลต่อไปนี้ครบถ้วน:

**แบบฟอร์ม — รายงานปัญหาระบบ RateSheetExtractor**

```
วันที่/เวลา: ______________________
ผู้รายงาน: ______________________
ระดับความรุนแรง: P1 / P2 / P3 / P4

[1] คำอธิบายปัญหา (อธิบายให้ชัดเจน):
_______________________________________________

[2] ขั้นตอนที่ทำก่อนเกิดปัญหา (ทำอะไร → เกิดอะไร):
1. _______________________________________________
2. _______________________________________________
3. _______________________________________________

[3] ข้อความ Error ที่ปรากฏ:
_______________________________________________

[4] Job Log ID ที่เกี่ยวข้อง (ถ้ามี):
_______________________________________________

[5] สายเรือ / ฟังก์ชันที่ได้รับผลกระทบ:
_______________________________________________

[6] ผลกระทบต่อการปฏิบัติงาน:
_______________________________________________

[7] สิ่งที่ลองทำแล้ว:
_______________________________________________

[8] ไฟล์แนบ (Screenshot, ไฟล์ที่มีปัญหา):
_______________________________________________
```

## 7.5 SOP-ESC-001: ขั้นตอนการส่งต่อปัญหา

<div class="procedure">

1. **ประเมิน** ระดับความรุนแรงตามตาราง 7.2
2. **รวบรวมข้อมูล** ตามแบบฟอร์มในข้อ 7.4
3. **ถ่ายภาพหน้าจอ** ของ Error และหน้าจอที่เกี่ยวข้องทั้งหมด
4. **ดาวน์โหลดไฟล์แนบ** ที่เกี่ยวข้อง (ถ้ามี)
5. **ส่งรายงาน** ให้ทีมเทคนิคตามช่องทางที่กำหนด
6. **บันทึก** หมายเลขอ้างอิงปัญหา (Ticket ID) ที่ได้รับ
7. **ติดตาม** ความคืบหน้าตามระยะเวลาเป้าหมาย

</div>

## 7.6 การบันทึกและติดตามปัญหา

เจ้าหน้าที่ควรจัดทำ **บันทึกปัญหา (Issue Log)** เพื่อติดตามปัญหาและผลการแก้ไข

| คอลัมน์ | รายละเอียด |
|---------|-----------|
| วันที่ | วันที่พบปัญหา |
| คำอธิบาย | สรุปปัญหาโดยย่อ |
| ระดับ | P1/P2/P3/P4 |
| ส่งต่อให้ | ชื่อทีมหรือบุคคล |
| วันที่แก้ไข | วันที่ปัญหาได้รับการแก้ไข |
| วิธีแก้ไข | สรุปการแก้ไขที่ดำเนินการ |

---

## 7.7 กรณีพิเศษ — Parser ไม่รองรับรูปแบบใหม่

เมื่อสายเรือส่ง Rate Sheet ในรูปแบบใหม่ที่ Parser ไม่รู้จัก:

<div class="procedure">

1. บันทึกข้อความ Error จาก Job Log
2. ดาวน์โหลดไฟล์แนบต้นฉบับ
3. แจ้งทีมเทคนิคพร้อมส่ง:
   - ไฟล์แนบต้นฉบับ
   - ข้อความ Error
   - ชื่อสายเรือและ Source Name
4. รอการอัปเดต Parser จากทีมเทคนิค
5. เมื่ออัปเดตแล้ว ลอง **Reparse** รายการที่ล้มเหลว

</div>

!!! tip "เคล็ดลับ"
    เก็บไฟล์ Rate Sheet ต้นฉบับไว้ใน folder ระหว่างรอการแก้ไข เพื่อให้วิเคราะห์ใหม่ได้เมื่อ Parser อัปเดตแล้ว
