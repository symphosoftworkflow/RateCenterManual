## 1.1 ความเป็นมาและวัตถุประสงค์ของระบบ

ระบบ **RateSheetExtractor** เป็นระบบสารสนเทศที่พัฒนาขึ้นเพื่อ **อ่าน วิเคราะห์ และจัดเก็บข้อมูลอัตราค่าระวางสินค้าทางทะเล** โดยอัตโนมัติ ซึ่งสายเรือต่าง ๆ ส่งมาทางอีเมลในรูปแบบไฟล์แนบ (PDF, Excel, หรือข้อความ)

ระบบนี้ช่วยลดขั้นตอนการบันทึกข้อมูลด้วยมือ ลดความผิดพลาด และเพิ่มความรวดเร็วในการนำข้อมูลอัตราค่าระวางมาใช้งาน

---

## 1.2 สถาปัตยกรรมระบบ

ระบบประกอบด้วย 3 ชั้นหลัก ดังนี้:

```
┌─────────────────────────────────────────────┐
│              Frontend (React)               │
│  หน้าจอผู้ใช้งาน — ทำงานบนเบราว์เซอร์        │
└─────────────────┬───────────────────────────┘
                  │ HTTPS / REST API
┌─────────────────▼───────────────────────────┐
│           Backend (Node.js + Express)       │
│  API Server — จัดการ Logic และ Authentication│
│  ┌────────────────────────────────────────┐ │
│  │    Python Parser Engine               │ │
│  │  วิเคราะห์ไฟล์แนบจาก 15 สายเรือ      │ │
│  └────────────────────────────────────────┘ │
└─────────────────┬───────────────────────────┘
                  │
┌─────────────────▼───────────────────────────┐
│            Database (PostgreSQL)            │
│  จัดเก็บข้อมูลผู้ใช้ อีเมล อัตราค่าระวาง   │
└─────────────────────────────────────────────┘
```

---

## 1.3 ส่วนประกอบหลัก

### 1.3.1 Frontend

ส่วนหน้าจอผู้ใช้งานพัฒนาด้วย **React.js + Vite + Tailwind CSS** ทำงานบนเบราว์เซอร์

**หน้าจอหลักที่มีในระบบ:**

| หน้าจอ | รายละเอียด | บทบาทที่เข้าถึงได้ |
|--------|-----------|-------------------|
| Login | หน้าเข้าสู่ระบบ | ทุกบทบาท |
| Dashboard | ภาพรวมสถิติและสถานะระบบ | ทุกบทบาท |
| Email Configuration | ตั้งค่า IMAP server | Admin, Superadmin |
| Source Emails | กำหนดแหล่งอีเมลต่อสายเรือ | Admin, Superadmin |
| Job Logs | ประวัติการทำงานและ Parse Review | Admin, Superadmin |
| Rate Query | ค้นหาอัตราค่าระวาง | ทุกบทบาท |
| Rate Export | ส่งออกอัตราค่าระวางรายเดือน | Admin, Superadmin |
| Surcharge Definitions | จัดการนิยาม Surcharge | Admin, Superadmin |
| Notification Emails | กำหนดอีเมลรับการแจ้งเตือน | Admin, Superadmin |
| Routing Updates | อัปเดตข้อมูล Routing จาก Excel | Admin, Superadmin |
| User Management | จัดการผู้ใช้งาน | Admin, Superadmin |
| Company Management | จัดการบริษัท | Superadmin เท่านั้น |
| Profile | ดูและแก้ไขข้อมูลส่วนตัว | ทุกบทบาท |

### 1.3.2 Backend API

ส่วนประมวลผลพัฒนาด้วย **Node.js + Express** รับคำขอจาก Frontend ผ่าน REST API และจัดการข้อมูลกับฐานข้อมูล

### 1.3.3 Python Parser Engine

ชุดโปรแกรมวิเคราะห์ที่เขียนด้วย Python รองรับสายเรือ **15 สายเรือ** ได้แก่:

| รหัส | ชื่อสายเรือ | รหัส | ชื่อสายเรือ |
|------|------------|------|------------|
| COSCO | COSCO Shipping | RCL | Regional Container Lines |
| ESL | Emirates Shipping | IAL | IAL |
| HMM | Hyundai Merchant Marine | JJS | JJS |
| KMTC | Korea Marine Transport | SINOKOR | Sinokor Merchant Marine |
| PIL | Pacific International Lines | SITC | SITC Container Lines |
| ZIM | ZIM Integrated Shipping | YANGMING | Yang Ming Marine Transport |
| CKLINE | CK Line | SMLINE | SM Line |
| TSLINE | TS Lines | | |

### 1.3.4 ฐานข้อมูล

**PostgreSQL** จัดเก็บข้อมูลทั้งหมด ประกอบด้วยตารางหลัก 13 ตาราง

## 1.4 กระบวนการทำงานโดยสรุป

```
อีเมลจากสายเรือ
      │
      ▼
[1] ดึงอีเมล (IMAP Fetch)
      │  raw_emails
      ▼
[2] วิเคราะห์ข้อมูล (Python Parser)
      │  parse_review_queue (pending_approval)
      ▼
[3] ผู้ดูแลระบบตรวจสอบ (Parse Review)
      │  อนุมัติ / ปฏิเสธ / Reparse
      ▼
[4] จัดเก็บอัตราค่าระวาง
      │  parsed_rate_rows
      ▼
[5] ผู้ใช้งานค้นหาและส่งออกข้อมูล
```

## 1.6 สภาพแวดล้อมการใช้งาน

| รายการ | ข้อมูล |
|--------|--------|
| สภาพแวดล้อม Production | Railway Cloud Platform |
| ฐานข้อมูล | PostgreSQL 18.x |
| Runtime | Node.js 18+, Python 3.10+ |
| การเข้าถึง | ผ่านเบราว์เซอร์ (HTTPS) |
| การยืนยันตัวตน | JWT Bearer Token |

    การเข้าถึง URL ของระบบและข้อมูลการเชื่อมต่อฐานข้อมูลให้ขอจากผู้ดูแลโครงสร้างพื้นฐาน
