# บทที่ 8 — การตรวจสอบและอนุมัติข้อมูล

*DOC-ADM-001 v1.0 | คู่มือผู้ดูแลระบบ*

---

## 8.1 ภาพรวม

หลังจากระบบวิเคราะห์ข้อมูลจากอีเมลแล้ว ข้อมูลจะอยู่ในสถานะ **"รอการอนุมัติ"** (Pending Approval) ก่อนที่จะถูกนำไปจัดเก็บในฐานข้อมูลอย่างเป็นทางการ

ผู้ดูแลระบบมีหน้าที่ **ตรวจสอบความถูกต้อง** และ **อนุมัติ** หรือ **ปฏิเสธ** ข้อมูลที่วิเคราะห์ได้

**สิทธิ์การเข้าถึง:** Admin และ Superadmin

## 8.3 การตรวจสอบรายการที่รอการอนุมัติ (Pending Approval)

### 8.3.1 ดูรายการ

แท็บ **"Pending Approval"** แสดงรายการที่วิเคราะห์สำเร็จและรอการอนุมัติ

| คอลัมน์ | คำอธิบาย |
|---------|---------|
| Source Name | ชื่อสายเรือ |
| หัวข้ออีเมล | Subject ของอีเมลต้นทาง |
| วันที่รับ | วันที่ดึงอีเมลเข้าระบบ |
| จำนวนแถว | จำนวนอัตราค่าระวางที่วิเคราะห์ได้ |
| สถานะ | Pending Approval |

### 8.3.2 ดูรายละเอียดอีเมลต้นทาง

<div class="procedure">

1. คลิกปุ่ม **"ดูอีเมล"** (View Email) ในแถวที่ต้องการ
2. ระบบเปิดหน้าต่างแสดงรายละเอียดอีเมล: หัวข้อ, ผู้ส่ง, วันที่, และไฟล์แนบ
3. คลิกชื่อไฟล์แนบเพื่อดาวน์โหลดและตรวจสอบเอกสารต้นฉบับ

</div>

## 8.4 การอนุมัติข้อมูล (Approve)

### 8.4.1 อนุมัติทีละรายการ

<div class="procedure">

1. ตรวจสอบข้อมูลในแถวที่ต้องการอนุมัติ
2. คลิกปุ่ม **"อนุมัติ"** (Approve) สีเขียว
3. ระบบยืนยันและย้ายข้อมูลไปยัง `parsed_rate_rows` ทันที
4. จำนวนรายการที่รอการอนุมัติลดลง

</div>

### 8.4.2 อนุมัติทั้งหมดของสายเรือ (Batch Approve)

<div class="procedure">

1. ระบุสายเรือที่ต้องการอนุมัติทั้งหมด
2. คลิกปุ่ม **"อนุมัติทั้งหมด"** (Batch Approve) สำหรับสายเรือนั้น
3. ระบบอนุมัติรายการที่รอทั้งหมดของสายเรือนั้นพร้อมกัน

</div>

!!! tip "เคล็ดลับ"
    ใช้ Batch Approve เมื่อท่านตรวจสอบเอกสารต้นฉบับแล้วและมั่นใจในความถูกต้อง เพื่อประหยัดเวลา

---

## 8.5 การปฏิเสธข้อมูล (Reject)

<div class="procedure">

1. คลิกปุ่ม **"ปฏิเสธ"** (Reject) สีแดง
2. ระบบบันทึกสถานะเป็น Rejected
3. ข้อมูลจะไม่ถูกนำเข้าฐานข้อมูลอัตราค่าระวาง

</div>

กรณีที่ควรปฏิเสธ:

- ข้อมูลวิเคราะห์ผิดพลาดชัดเจน (POL/POD ไม่ถูกต้อง อัตราผิดปกติ)
- Rate Sheet เป็นฉบับทดสอบหรือไม่ใช่อัตราจริง
- อีเมลนั้นไม่ใช่ Rate Sheet

---

## 8.6 การ Reparse (วิเคราะห์ใหม่)

ในกรณีที่การวิเคราะห์ล้มเหลวหรือผลลัพธ์ไม่ถูกต้อง สามารถสั่งให้ระบบวิเคราะห์ใหม่ได้

<div class="procedure">

1. ค้นหารายการในแท็บ **"Parse Failures"** หรือแท็บ **"Pending Approval"**
2. คลิกปุ่ม **"Reparse"** (สีม่วง)
3. ระบบลบผลการวิเคราะห์เดิมและเริ่มวิเคราะห์ใหม่โดยอัตโนมัติ
4. รอสักครู่แล้วรีเฟรชหน้า เพื่อดูผลการวิเคราะห์ใหม่

</div>

!!! note "หมายเหตุ"
    Reparse ใช้สำหรับกรณีที่ Parser ได้รับการอัปเดตใหม่หลังจากที่อีเมลถูกประมวลผลแล้ว หรือเมื่อต้องการทดสอบผลลัพธ์การวิเคราะห์ใหม่

---

## 8.7 การจัดการรายการที่ล้มเหลว (Parse Failures)

แท็บ **"Parse Failures"** แสดงรายการที่ระบบไม่สามารถวิเคราะห์ได้

**ขั้นตอนการจัดการ:**

<div class="procedure">

1. เปิดแท็บ **"Parse Failures"**
2. คลิก **"ดูอีเมล"** เพื่อตรวจสอบเอกสารต้นฉบับ
3. ตรวจสอบข้อความ Error ที่ระบบแสดง
4. หากเป็นปัญหาของเอกสาร (รูปแบบเปลี่ยน): แจ้งทีมเทคนิค
5. หากเป็นปัญหาชั่วคราว: ลอง **Reparse**
6. หากไม่สามารถแก้ไขได้: **Reject** และบันทึกเป็นข้อมูลสำหรับทีมเทคนิค

</div>

---

## 8.8 สถานะของรายการใน Parse Review Queue

| สถานะ | ความหมาย | การดำเนินการที่ทำได้ |
|-------|---------|-------------------|
| `pending_approval` | รอการตรวจสอบ | Approve, Reject, Reparse |
| `approved` | อนุมัติแล้ว | ดูข้อมูลเท่านั้น |
| `rejected` | ปฏิเสธแล้ว | Reparse |
| `parse_failed` | วิเคราะห์ล้มเหลว | Reparse, Reject |

!!! warning "ข้อควรทราบ"
    การอนุมัติซ้ำ (Approve รายการเดิมมากกว่าหนึ่งครั้ง) จะทำให้ข้อมูลซ้ำกันในฐานข้อมูล ควรตรวจสอบก่อนเสมอว่าอีเมลนั้นถูกอนุมัติแล้วหรือยัง
