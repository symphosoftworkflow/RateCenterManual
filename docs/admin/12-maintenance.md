# บทที่ 12 — การบำรุงรักษาระบบ

*DOC-ADM-001 v1.0 | คู่มือผู้ดูแลระบบ*

---

## 12.1 การบำรุงรักษาเชิงป้องกัน (Preventive Maintenance)

### 12.1.1 รายการตรวจสอบรายสัปดาห์

| รายการ | วิธีตรวจสอบ | ผลที่คาดหวัง |
|--------|-----------|------------|
| ตรวจสอบ Job Logs ล้มเหลว | เมนู Job Logs → กรอง Failed | ไม่มี Job ล้มเหลวที่ยังไม่ได้รับการจัดการ |
| ตรวจสอบรายการรอการอนุมัติ | แท็บ Parse Review | รายการไม่สะสมมากเกิน |
| ตรวจสอบ Source Email ที่ปิดอยู่ | เมนู Source Emails | ทุก Source ที่ใช้งานอยู่ในสถานะ Active |
| ตรวจสอบการแจ้งเตือน | เมนู Notification Emails | อีเมลที่กำหนดยังใช้งานได้ |

### 12.1.2 รายการตรวจสอบรายเดือน

| รายการ | วิธีตรวจสอบ |
|--------|-----------|
| ตรวจสอบบัญชีผู้ใช้งานที่ไม่ได้ใช้ | เมนู User Management → ดูผู้ใช้ที่ไม่มีการเข้าสู่ระบบนาน |
| ทบทวน Surcharge Definitions | ตรวจสอบว่ายังครบถ้วนและเป็นปัจจุบัน |
| ตรวจสอบการตั้งค่า IMAP | ทดสอบการเชื่อมต่ออีเมล |

## 12.2 การสำรองข้อมูล (Backup)

การสำรองข้อมูลระบบดำเนินการโดยโครงสร้างพื้นฐาน Railway Cloud โดยอัตโนมัติ อย่างไรก็ตาม ผู้ดูแลระบบควรทำการ **Export ข้อมูลอัตราค่าระวาง** เป็นประจำ

**วิธี Export ข้อมูลเพื่อสำรอง:**

<div class="procedure">

1. เข้าหน้า **Rate Export** ในเมนูหลัก
2. เลือกเดือนที่ต้องการ Export
3. เลือกรูปแบบ (Sale Person Format หรือ FWD Format)
4. ดาวน์โหลดและจัดเก็บไฟล์ Excel ในที่ปลอดภัย

</div>

## 12.3 การจัดการเมื่อระบบมีปัญหา

### 12.3.1 ระบบล็อกอินไม่ได้

| สาเหตุ | แนวทางแก้ไข |
|--------|-----------|
| ลืมรหัสผ่าน | ให้ Admin/Superadmin รีเซ็ตรหัสผ่าน |
| บัญชีถูกระงับ | ให้ Superadmin เปิดการใช้งานอีกครั้ง |
| Session หมดอายุ | ปิดเบราว์เซอร์และเปิดใหม่ แล้วเข้าสู่ระบบอีกครั้ง |
| ระบบไม่ตอบสนอง | ตรวจสอบ URL และการเชื่อมต่ออินเทอร์เน็ต |

### 12.3.2 การดึงอีเมลล้มเหลว

| ปัญหา | สาเหตุที่พบบ่อย | แนวทางแก้ไข |
|-------|----------------|------------|
| Authentication Failed | รหัสผ่าน IMAP หมดอายุ หรือเปลี่ยน | อัปเดตรหัสผ่าน IMAP ในการตั้งค่า |
| Connection Timeout | เครือข่ายไม่เสถียร หรือ IMAP Server down | รอสักครู่แล้วลองใหม่ |
| Certificate Error | SSL Certificate หมดอายุ | แจ้งทีมเทคนิค |
| Too many connections | เปิดการดึงอีเมลหลายครั้งพร้อมกัน | รอให้กระบวนการปัจจุบันเสร็จ |

### 12.3.3 Parser ล้มเหลวสำหรับสายเรือหนึ่ง

<div class="procedure">

1. ดาวน์โหลดไฟล์แนบจากอีเมลนั้น (ผ่าน Job Logs → ดูอีเมล)
2. ตรวจสอบรูปแบบไฟล์ว่าเปลี่ยนแปลงจากปกติหรือไม่
3. ลอง Reparse หนึ่งครั้ง
4. หากยังล้มเหลว แจ้งทีมเทคนิคพร้อมแนบไฟล์แนบและข้อความ Error

</div>

### 12.3.4 ข้อมูลอัตราค่าระวางผิดพลาด (Incorrect Data)

หากพบว่าข้อมูลที่อนุมัติแล้วมีค่าผิดพลาด:

<div class="procedure">

1. แจ้งทีมเทคนิคพร้อมระบุ: สายเรือ, เดือน, เส้นทาง POL/POD, และค่าที่ผิด
2. ทีมเทคนิคจะดำเนินการแก้ไขตรงในฐานข้อมูล
3. หลังแก้ไข ให้ Export ข้อมูลใหม่และแจ้งผู้ใช้งานที่ได้รับผลกระทบ

</div>

!!! danger "ข้อสำคัญ"
    ผู้ดูแลระบบไม่ควรแก้ไขข้อมูลตรงในฐานข้อมูล (Direct DB Edit) โดยไม่ได้รับการอนุมัติจากหัวหน้า เนื่องจากอาจส่งผลต่อข้อมูลอื่น ๆ ในระบบ

## 12.4 การติดต่อทีมสนับสนุน

กรณีที่ไม่สามารถแก้ไขปัญหาได้เอง ให้รวบรวมข้อมูลต่อไปนี้ก่อนติดต่อทีมเทคนิค:

| รายการ | รายละเอียด |
|--------|-----------|
| คำอธิบายปัญหา | อธิบายปัญหาที่พบโดยละเอียด |
| ขั้นตอนที่ทำก่อนเกิดปัญหา | ทำอะไรก่อนที่ปัญหาจะเกิด |
| Error Message | ข้อความผิดพลาดที่ระบบแสดง (Screenshot) |
| Job Log ID | หมายเลข Job ที่เกี่ยวข้อง |
| วันและเวลาที่เกิดปัญหา | ระบุให้ชัดเจน |
| ผู้ใช้งานที่ได้รับผลกระทบ | ชื่อ และ บทบาท |

!!! tip "แนวปฏิบัติที่ดี"
    ถ่ายภาพหน้าจอ (Screenshot) ของข้อความ Error และหน้าจอที่เกี่ยวข้องเสมอ เพื่อให้ทีมเทคนิควิเคราะห์ปัญหาได้รวดเร็วขึ้น
